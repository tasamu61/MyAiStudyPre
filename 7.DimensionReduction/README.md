# ７．次元削減（PCA） ― 5つの諸元を2つの軸に落とす

機械学習を実用的に動かすテクニックのひとつとして次元削減があり、その実現にはいくつかの手法があるが、ここでは代表的なひとつであるPCAをもちいて、実際にもよくありそうな自動車の諸元の次元削減を例に説明する。

## 7.1 次元削減とは

次元削減の役割は大きく2つある。

**① 人間が見るため（可視化）**

人間は3次元までしか直感的に把握できない。5つも10もある諸元をそのまま眺めても、
データ同士の距離感や似ている・似ていないの判断はできない。2〜3次元に落とし込んで
初めて、散布図として目で見て理解できるようになる。本章のデモが分かりやすい例である。

**② 機械学習の前処理として（AIに学習させるため）**

自然に存在するデータは非常に冗長であり、膨大である。そのまま扱うと、著しく処理に時間がかかり
現実的なレスポンスが得られなかったり、有効な結果を導くことができなかったりする。そのため、
PCAのような手法を用いて有効なデータになるように軽量化をはかっている。

> 💡 **余談：次元削減が使われてきた例（顔認証）**
>
> 画像処理「顔認証」も次元削減が多用される分野である。100×100ピクセルのグレースケール顔写真は、
> 1ピクセル＝1次元とみなすと1万次元のデータになる。しかし、有用な情報はその一部に過ぎず、
> 圧縮することによって実用に耐える処理時間・精度が得られるようなアプローチが使われたこともある。

## 7.2 諸元からPC1〜5を導く過程

以下の①〜⑤の番号は、サンプルプログラム（HTMLデモ・ノートブック）のコード中のコメントとも対応させている。

PCによる次元削減の流れは以下となる。

①標準化する
排気量、燃費、価格など単位や数値範囲が違う諸元を、同様な数値レベルとして比較できるようにする。

②諸元間の関係を調べる
「排気量が大きいと馬力も大きい」など、互いに関連して動く諸元を見つける。

③情報をよく表す新しい軸を求める
元の「排気量」「馬力」といった軸ではなく、データの特徴を最もよく表す方向を新しい軸（主成分）とする。

④重要な軸だけを残す
情報量の多い主成分を残し、情報量の少ない主成分を捨てる。

⑤少ない次元でデータを表現する
例えば5個の諸元を、特徴をなるべく維持したまま2個の値に圧縮する。

## Step0: 各諸元（元データ）

```java
String[] names = new String[n];
double[][] data = new double[n][m];
for (int i = 0; i < n; i++) {
    names[i] = records.get(i).name();
    data[i] = records.get(i).values();
}
```

`DataSet`（`CarDataSet`）から名前と数値を取り出して配列に詰め替えているだけであり、
この時点ではまだ何も計算していない。排気量・価格・乗員という、単位も桁もバラバラな
生の数字がそのまま並んでいる状態である。

---

## Step1: 標準化

```java
for (int j = 0; j < m; j++) {
    double sq = 0;
    for (int i = 0; i < n; i++) sq += Math.pow(data[i][j] - mean[j], 2);
    std[j] = Math.sqrt(sq / n);
}
double[][] z = new double[n][m];
for (int i = 0; i < n; i++)
    for (int j = 0; j < m; j++)
        z[i][j] = (data[i][j] - mean[j]) / std[j];
```

「各諸元を数値的に同一レベルでみれるように加工する」処理である。

排気量は「660〜3000」、乗員は「2〜7」というように、桁もばらつきの大きさも全く異なる。
このままでは、排気量のわずかな違いが計算上は大きな差として扱われ、乗員数の違いが
埋もれてしまう。そこで各諸元ごとに `(値 − 平均) / 標準偏差` という変換を行う。これは
「その諸元の中で、平均よりどれだけ離れているかを "標準偏差いくつ分" という共通のもの
さしで測り直す」操作である（統計学ではこれを**z-score化**と呼ぶ）。

**平均・標準偏差の計算結果：**

| 変数 | 平均 | 標準偏差 |
|---|---|---|
| 排気量(cc) | 1860.00 | 809.11 |
| 価格(万円) | 248.33 | 84.15 |
| 乗員 | 4.67 | 1.49 |

**標準化後データの一覧：**

| 名前 | 排気量(cc) | 価格(万円) | 乗員 |
|---|---|---|---|
| 軽自動車 | -1.483 | -1.287 | -0.447 |
| コンパクト | -1.063 | -0.812 | 0.224 |
| ヴァン | 0.173 | -0.218 | 1.565 |
| セダン | 0.173 | -0.099 | 0.224 |
| スポーツカー | 0.791 | 0.614 | -1.789 |
| 高級車 | 1.409 | 1.802 | 0.224 |

軽自動車は3諸元ともマイナス側に寄っており、高級車は排気量・価格がプラス側に
大きく振れている。スポーツカーだけ乗員が-1.789と突出して低く、これが後の
Step4（第2主成分＝乗員軸）でスポーツカーが特徴的な位置に来る理由になっている。

## Step2: 共分散行列の計算

```java
double[][] cov = new double[m][m];
for (int a = 0; a < m; a++) {
    for (int b = 0; b < m; b++) {
        double s = 0;
        for (int i = 0; i < n; i++) s += z[i][a] * z[i][b];
        cov[a][b] = s / n;
    }
}
```

「各諸元同士が同じ傾向を示すなら正の大きな数、逆の傾向を示すなら負の大きな数となる
計算」である。諸元aとbについて、各データの標準化した値同士を掛け算して平均を取る。

- 排気量が大きい車（標準化後がプラス）は価格も高い（標準化後もプラス）傾向が強ければ
  プラス×プラス＝プラスの値が積み上がる
- 片方がプラスでもう片方がマイナスの傾向が多ければマイナスの値が積み上がる
- 関係がバラバラならプラスとマイナスが打ち消し合いゼロに近づく

つまり `cov[a][b]` は「aとbが一緒に大きく/小さくなる傾向が強いほど絶対値が大きくなる」
指標である。標準化済みのため、これは統計学でいう**相関係数**とほぼ同じ意味を持つ
行列（**共分散行列**）になっている。

**計算結果：**

| | 排気量(cc) | 価格(万円) | 乗員 |
|---|---|---|---|
| 排気量(cc) | 1.000 | 0.957 | -0.061 |
| 価格(万円) | 0.957 | 1.000 | -0.111 |
| 乗員 | -0.061 | -0.111 | 1.000 |

排気量と価格の関係が0.957と非常に強いプラスになっている。「排気量が大きい車は
価格も高い」という傾向がそのまま数値化された結果である。一方、乗員との関係は
-0.06〜-0.11程度であり、排気量・価格ほど強くは連動していない。

## Step3・Step4の準備: 固有値分解（ヤコビ法）

```java
EigenResult eig = jacobiEigen(cov);

Integer[] order = new Integer[m];
for (int i = 0; i < m; i++) order[i] = i;
Arrays.sort(order, (x, y) -> Double.compare(eig.values[y], eig.values[x]));
```

Step2で「排気量と価格が強く連動している」ことが分かったため、この2つをひとまとめに
した軸を作れば効率よく情報を圧縮できる。ヤコビ法（対称行列に対する反復的な固有値
計算アルゴリズム）でこの「軸の向き（固有ベクトル）」と「軸方向の広がりの大きさ
（固有値）」を求める。

**固有値の計算結果（大きい順）：**

| 軸 | 固有値 |
|---|---|
| 1番目 | 1.972 |
| 2番目 | 0.986 |
| 3番目 | 0.042 |

1番目の軸が圧倒的にデータの広がりを説明しており、これを第1主成分として採用する。

---

## Step3: 第1主成分の係数を求める

```java
int idx1 = order[0];
double ratio1 = eig.values[idx1] / totalVar * 100;
printComponentTable("Step3: 第1主成分の係数を求める", features, eig.values[idx1], ratio1, eig.vectors, idx1);
```

固有値が最大の軸を第1主成分として採用する処理である。

**計算結果：** 固有値 1.972 ／ 寄与率 65.7%

| 諸元 | 係数 |
|---|---|
| 排気量(cc) | -0.700 |
| 価格(万円) | -0.703 |
| 乗員 | 0.124 |

排気量と価格の係数（-0.700, -0.703）が乗員の係数（0.124）よりずっと大きい。
この軸はほぼ「排気量と価格をセットにした軸」＝**車格・グレードの高さ**を
表していると解釈できる（符号がマイナスのため、この軸の値が大きい車ほど
排気量・価格が小さい、という向きになっている点に注意）。

## Step4: 第2主成分の係数を求める

```java
int idx2 = order[1];
double ratio2 = eig.values[idx2] / totalVar * 100;
printComponentTable("Step4: 第2主成分の係数を求める", features, eig.values[idx2], ratio2, eig.vectors, idx2);
```

Step3と同じ考え方で、2番目に広がりが大きい軸を採用する。この軸は第1主成分と
数学的に**直交**しており、第1主成分では拾いきれなかった別の傾向を表す。

**計算結果：** 固有値 0.986 ／ 寄与率 32.9%

| 諸元 | 係数 |
|---|---|
| 排気量(cc) | 0.114 |
| 価格(万円) | 0.061 |
| 乗員 | 0.992 |

乗員の係数（0.992）が圧倒的に大きく、排気量・価格はほぼ無視できる水準である。
この軸は**乗員数（実用性）**をほぼそのまま表しており、第1主成分が拾いきれ
なかった「乗員数の違い」をこちらが担っていることが分かる。

---

## Step5: 各データをPC1・PC2へ変換

```java
double[][] pc = new double[m][2];
for (int k = 0; k < 2; k++) {
    int idx = order[k];
    for (int a = 0; a < m; a++) pc[a][k] = eig.vectors[a][idx];
}

double[][] projected = new double[n][2];
for (int i = 0; i < n; i++) {
    for (int k = 0; k < 2; k++) {
        double s = 0;
        for (int a = 0; a < m; a++) s += z[i][a] * pc[a][k];
        projected[i][k] = s;
    }
}
```

Step3・4で求めた係数のセットを各データに当てはめ、1台ずつ新しい2つの数値
（PC1, PC2）に変換する処理である。内側のループでは「標準化した排気量×排気量の
係数＋標準化した価格×価格の係数＋標準化した乗員×乗員の係数」を計算しており、
これによって3つあった諸元がPC1・PC2というたった2つの数値に圧縮される。
これが**次元削減**の本体である。

**計算結果：**

| 名前 | PC1 | PC2 |
|---|---|---|
| 軽自動車 | 1.888 | -0.691 |
| コンパクト | 1.343 | 0.051 |
| ヴァン | 0.226 | 1.558 |
| セダン | -0.024 | 0.235 |
| スポーツカー | -1.207 | -1.646 |
| 高級車 | -2.226 | 0.493 |

PC1は軽自動車(1.888)→高級車(-2.226)まで、車格の低い順〜高い順にきれいに
並んでいる（Step3の解釈通りである）。PC2は乗員2人のスポーツカーが最も低い値
(-1.646)、乗員7人のヴァンが最も高い値(1.558)であり、乗員数の少ない順〜多い順に
対応している（Step4の解釈通りである）。3諸元の情報が、この2つの数値でかなり
本質を表せていることが数値でも確認できる。

## (参考) 寄与率

```java
System.out.println("**累積寄与率（第1主成分＋第2主成分）: "
        + String.format("%.1f", ratio1 + ratio2) + "%**\n");
```

Step5で2つに圧縮した結果、元の情報（分散）のうち何%を保持できているかを
示す補足情報である。次元削減の計算そのものには関与しない。

**計算結果：** 累積寄与率 = 65.7% + 32.9% = **98.6%**

3諸元の情報のうち98.6%を2次元だけで説明できている。捨てているのは1.4%分
（3番目の軸、固有値0.042）のみであり、この次元削減はかなりうまくいっていると
言える。

## FINAL: グラフ

```java
int cx = (int) Math.round((p[i][0] - minX) / (maxX - minX) * (width - 1));
int cy = (int) Math.round((p[i][1] - minY) / (maxY - minY) * (height - 1));
int row = height - 1 - cy;
grid[row][cx] = symbols[i].charAt(0);
```

Step5で求めたPC1・PC2の値を平面上の座標に変換し、テキストの格子に打点する
処理である。`(p[i][0]-minX)/(maxX-minX)` は「全データの中でこの点がどのあたりの
位置か」を0〜1の割合に直し、それをグラフの横幅・縦幅のマス目番号に変換して
いるにすぎない。これにより、排気量・価格・乗員という3つの数字が、平面上の
1つの点として視覚化される。

**イメージ（A=軽自動車〜F=高級車）：**

```
PC2
                    D(ヴァン)
        B(コンパクト)
    A(軽自動車)        F(高級車)
                E(セダン)
E(スポーツカー)
--------------------------------> PC1
```

横軸（PC1）方向に軽自動車→高級車という車格の並びが、縦軸（PC2）方向に
スポーツカー(乗員少)→ヴァン(乗員多)という乗員数の並びが、それぞれ視覚的に
確認できるグラフになっている。
