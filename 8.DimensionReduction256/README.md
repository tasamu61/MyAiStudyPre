# ８．次元削減２ ― 256次元のドットパターンを圧縮する

7章では、排気量・価格・乗員など**5個以下の諸元**を2次元に落とした。本章では題材を変え、
16×16のドットパターン（**256次元**）を圧縮する。諸元の数が桁違いに増えることで、7章とは
違う工夫が必要になる場面と、「次元を減らす」ことと「実際のデータ量を減らす」ことが
別問題であるという点を、具体的な数値で確認する。

## 8.1 7章との違い：諸元数とデータ件数の大小が逆転する

7章では「諸元の数（3〜5個）」より「データの件数（5〜6台）」の方が多かった。本章の
256次元パターンでは、この大小関係が逆転し、「諸元の数（256個）」の方が「データの件数
（数十件程度）」よりずっと多くなる。

この違いにより、PCAの計算方法を変える必要が出てくる。7章では256×256（のような）
大きな共分散行列を直接扱っても問題にならないが、本章のように諸元数が件数よりずっと
多い場合、**データ件数×データ件数という小さい方の行列（グラム行列）を固有値分解し、
そこから256次元側の主成分を逆算する**という「デュアルトリック」を使う方が効率的である
（`08-1DimReduction256.ipynb`、`DimReductionDemo.java`とも、この方式で実装している）。

PCAの目的・意味（分散を最大にする方向を探す）そのものは7章とまったく同じであり、
変わるのは計算の都合だけである。

## 8.2 次元削減だけでは、データ量は減らない

256個のfloat値を16個のfloat値に減らしても（256→16）、**1個の値のサイズ（float64＝8バイト）
はそのままなので、データ量は単純に16/256＝約6%に減るだけ**である。しかも、たとえば
元の画像が0/1の2値（1ビットで表せる）であった場合、圧縮後の16個のfloat64（128バイト）は、
元の画像をビットのまま保存した場合（256/8＝32バイト）より**かえって大きくなる**。

「次元の数（floatの個数）を減らすこと」と「1個の値が占めるサイズ（ビット数）を
減らすこと」は独立した別の問題であり、実際にデータ量を減らすには、次元削減のあとに
**量子化**（連続値を少ないビット数の整数に丸める処理）を組み合わせる必要がある。

## 8.3 サンプルプログラム

Pythonを中心に、同じ内容をJavaに移植したものを補足として用意した。

- **[08-1DimReduction256.ipynb](https://colab.research.google.com/github/tasamu61/MyAiStudyPre/blob/main/8.DimensionReduction256/08-1DimReduction256.ipynb)**（メイン）：
  scikit-learnの`PCA`を使い、以下を一通り扱うノートブックである。
  1. 6種類の基本パターン（十字・丸・斜め線・市松模様・バツ・ランダム）の生成とノイズ付与
  2. 学習データ・推論用データの作成、PCAによる256→K次元への圧縮
  3. 「256次元のまま判定する分類器」と「K次元に減らして判定する分類器」（どちらもk-NN）の比較
  4. 量子化（float64→8/6/4/3/2/1ビット）による、実際のデータ量と正解率の変化
  5. （参考）符号付きランダム射影による、学習なしでビットを直接得る方法との比較
- **[DimReductionDemo.java](DimReductionDemo.java)**（付け足し）：
  上記と同じ内容を、外部ライブラリを使わず1本のJavaファイルに移植したもの。PCAは
  デュアルトリックをヤコビ法（7章の`PCA2D.java`と同じアルゴリズム）で自前実装しており、
  numpy/scikit-learnが内部で何をしているかをコードで追いたい場合に参照する。
  乱数の扱いがPythonと異なるため、数値はノートブックと完全には一致しないが、傾向
  （K次元の方がノイズに強い、量子化しても精度が落ちにくい、等）は再現される。

## 8.4 実際のデータ量の比較

ノートブックのデフォルト設定（学習20件/クラス・ノイズ5%、推論20件/クラス・ノイズ10%、
K=16）で実行すると、以下のような結果になる（乱数の影響で多少前後する）。

| 表現 | 1件のバイト数 | 正解率 |
|---|---:|---:|
| 256次元のまま（削減前、1ビット/画素） | 32.0B | 90.8% |
| 16次元、float64（量子化なし） | 128.0B | 98.3% |
| 16次元、8ビット量子化 | 16.0B | 98.3% |
| 16次元、6ビット量子化 | 12.0B | 98.3% |
| 16次元、4ビット量子化 | **8.0B** | **99.2%** |
| 16次元、3ビット量子化 | 6.0B | 97.5% |
| 16次元、2ビット量子化 | 4.0B | 98.3% |
| 16次元、1ビット量子化 | 2.0B | 87.5% |

4ビット量子化（1件わずか8バイト）の時点で、元画像を理論上の最小サイズ（1ビット/画素、
32バイト）で保存した場合の**4分の1のサイズでありながら、正解率はむしろ元の256次元
（90.8%）を上回る**。次元削減と量子化を両方行って初めて、意味のあるデータ量削減に
なることが数値で確認できる。

## 8.5 （参考）次元削減そのものをビットで処理する方法

8.2〜8.4は「まずfloatで次元を減らし、そのあと量子化でビットにする」という2段階の
やり方だった。これとは別に、**最初から1ビットを直接出す**方法もある。代表的なのが
符号付きランダム射影（Signed Random Projection / SimHash）で、ランダムな方向を
いくつか用意し、データとの内積の符号（＋なら1、－なら0）だけを採用する。学習は
一切不要で、計算コストもほぼゼロである。

ただし、同じデータで試すと、この方法は量子化を使った方式に明確に劣る。

| 方式 | 1件のバイト数 | 正解率 |
|---|---:|---:|
| 符号付きランダム射影、16ビット | 2.0B | 62.5% |
| 符号付きランダム射影、8ビット | 1.0B | 60.8% |
| 符号付きランダム射影、4ビット | 0.5B | 40.0% |
| 符号付きランダム射影、2ビット | 0.2B | 30.0% |
| （比較）16次元、2ビット量子化（8.4より） | 4.0B | 98.3% |
| （比較）256次元そのまま | 32.0B | 90.8% |

同じ2バイトで比べても、符号付きランダム射影（16ビット＝62.5%）は量子化方式
（16次元2ビット＝98.3%）に遠く及ばない。理由は単純で、PCAは学習データを見て
「分類に有効な方向」を選んでいるのに対し、ランダム射影は学習データを一切見ずに
方向を乱数で決めているため、同じビット数では情報の使い方に無駄が多いからである。
「学習せずにビットを直接得られる」という手軽さと引き換えに、精度は犠牲になる、
という関係になっている。

## まとめ

- 諸元数(256)がデータ件数よりずっと多い場合は、デュアルトリックでPCAを効率よく計算できる（8.1）
- 次元削減（floatの個数を減らす）と量子化（1個のビット数を減らす）は別問題であり、
  実際にデータ量を減らすには両方が必要である（8.2, 8.4）
- 学習済みの方向（PCA）を使う量子化と、学習なしでビットを得るランダム射影を比べると、
  同じビット数ではPCA側が明確に有利である（8.5）
